Enhancement One: Software Design and Engineering

Overview

My first enhancement focused on improving the organization, maintainability, and usability of InventoryApp. The original application had a relatively simple structure, with several responsibilities handled directly by the application's activities.

I reorganized the application into separate components responsible for inventory data, business logic, and database operations. This included creating an InventoryItem model, an InventoryRepository for data access, and an InventoryService for validation and inventory-related operations.

Improvements

  • Separated user interface logic from business logic and database operations.
  • Introduced reusable model, repository, and service classes.
  • Improved inventory displays using RecyclerView.
  • Added improved input validation and error handling.
  • Improved the overall organization and maintainability of the application.

Skills Demonstrated

This enhancement demonstrates my understanding of software architecture, object-oriented programming, separation of concerns, and application maintainability. It also helped me better understand how to organize larger projects so that future changes are easier to implement.

Enhancement Two: Algorithms and Data Structures

Overview

My second enhancement focused on adding more advanced algorithmic functionality to InventoryApp. The original application allowed users to manage inventory but did not provide a way to prioritize items that needed to be restocked.

To improve this, I implemented a restock recommendation system using Java's PriorityQueue data structure. The system examines inventory quantities and reorder thresholds to identify items that need attention.

Restock Priority Algorithm

Each inventory item has a reorder threshold that represents the quantity at which the item should be considered for restocking. The application calculates the shortage using the difference between the reorder threshold and the current inventory quantity.

Items at or below their reorder threshold are placed into a priority queue. Items with larger shortages are given higher priority so that the most urgent restocking needs appear first.

Improvements

  • Added reorder thresholds for inventory items.
  • Implemented a PriorityQueue to rank restock recommendations.
  • Used a custom comparator to determine restocking priority.
  • Added a dedicated restock recommendations view.
  • Improved inventory searching, sorting, and filtering functionality.

Skills Demonstrated

This enhancement demonstrates my ability to select and implement an appropriate data structure to solve a practical problem. Using a priority queue allowed me to organize inventory items based on urgency while keeping the algorithm separate from the user interface.

Building the priority queue takes O(n log n) time when qualifying items are inserted individually. This provides an opportunity to explain algorithmic complexity and the trade-offs involved in choosing a data structure.

Enhancement Three: Databases

Overview

My third enhancement focused on improving the application's SQLite database. The original version used a relatively basic database structure that supported simple inventory operations but had limited support for more advanced features.

I redesigned the database to use a more organized relational structure. This allowed the application to store additional information, maintain inventory history, and generate useful reports.

Database Design

The updated database includes four main tables:

  • Users: Stores user account information, including securely hashed passwords.
  • Categories: Stores inventory category information.
  • Inventory: Stores item information, quantities, prices, and reorder thresholds.
  • Inventory Transactions: Records changes made to inventory quantities over time.

Improvements

  • Created a more normalized relational database structure.
  • Added foreign key relationships between related tables.
  • Added database constraints to help protect data integrity.
  • Implemented transaction history for inventory changes.
  • Added reporting features for inventory and category information.
  • Improved password storage and database security.
  • Used database transactions to keep related updates consistent.

Skills Demonstrated

This enhancement demonstrates my understanding of relational database design, normalization, SQL queries, data integrity, and secure data management.

The improved database allows InventoryApp to support more advanced functionality while maintaining a clearer structure. It also demonstrates how database design affects the reliability and usefulness of an application.
